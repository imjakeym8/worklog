# 📝 Worklog: 2026-09-20

## ⏱️ Activity Breakdown

Built out the Worklog application across Milestones 1–5 by setting up FastAPI and PostgreSQL persistence, connecting the Next.js frontend to the backend, adding GitHub OAuth and GitHub App repository access, configuring private Supabase object storage for image attachments, and implementing Markdown import/export with groundwork for safe GitHub publishing.

## 🛠️ Detailed Notes

Set up and validated the backend with FastAPI, PostgreSQL, Alembic, and async database access. Core local commands included `python -m alembic upgrade head`, `python -m app.seed`, and `python -m uvicorn app.main:create_app --factory --host localhost --port 8000 --reload`. API behavior was verified through FastAPI Swagger at `http://localhost:8000/docs`, PostgreSQL, and pgAdmin.

Connected the Next.js frontend to FastAPI using a centralized API layer and environment-based backend URL rather than hardcoded endpoints. CRUD operations now persist through PostgreSQL instead of in-memory sample data, with create, update, delete, filtering, and reload persistence verified.

Implemented GitHub OAuth for authentication and session-based Worklog ownership. Added GitHub App configuration for repository-level access, using server-side App JWT generation, installation discovery, and short-lived installation tokens. GitHub repository: https://github.com/imjakeym8/worklog

Configured private Supabase S3-compatible object storage for one JPEG/PNG attachment per Worklog, including 5 MB validation, private access, generated storage keys, image preview, replacement, deletion, and cleanup. The backend uses path-style S3 requests so the storage layer remains compatible with Supabase.

Implemented Markdown portability using canonical YAML frontmatter and structured Worklog sections. Added `.md` import/export, safe YAML parsing, support for legacy `blocker:` → `blockers`, duplicate detection, source/content hashing, and explicit confirmation before updating previously imported Markdown. PostgreSQL remains the canonical source of truth.

Key technical decisions:

* Keep PostgreSQL as the authoritative Worklog store.
* Keep image binaries out of PostgreSQL and use private object storage.
* Keep GitHub secrets/tokens server-side only.
* Use GitHub App access for repository operations rather than browser-held tokens.
* Keep Markdown import/export deterministic so Worklog data can round-trip safely.
* Keep GitHub publishing explicit rather than automatic.
